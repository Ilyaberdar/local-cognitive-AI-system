# Проекты, агентный цикл и Workflow: проверка реализации

Дата: 2026-09-23. Изменения находятся в рабочем дереве.

## Реализовано

- Projects выше Chats, высота по содержимому, тонкий разделитель и общая прокрутка. Оба раздела сворачиваются с сохранением состояния; вложенные чаты компактные, без постоянных даты/канала. Создание из свёрнутого раздела раскрывает нужную секцию.
- Проект хранит имя и каноническую существующую директорию. Создание, переименование, архивирование/восстановление; Electron предоставляет системный выбор папки.
- Task и Schedule выбирают Project и Access. Workflow остаётся шаблоном. Задача без проекта получает постоянную управляемую папку. Создать новый проект можно прямо из формы, сохранив её черновик.
- Проектные чаты и Workflow агенты используют строгий JSON-цикл с результатами инструментов, проверками версий файлов, пределами выполнения и сохранёнными операциями. Советники исследуют файлы с правами чтения.
- Workflow сохраняет workspace/task/settings/model targets. Ожидание подтверждения переживает перезапуск. Неопределённые эффекты блокируют повтор и переходы retry. Plugin actions выполняются только по исходному запросу пользователя, с сохранённым содержимым и проверкой конфигурации назначения.
- Память разделена по проекту/задаче, пользователю и каналу. История каждого чата и запуска отдельная.

Итоговый `npm test`: **347 passed, 0 failed, 1 skipped** (348 с учётом вложенных тестов). Сборки TypeScript и frontend проходят; `git diff --check` без ошибок.

Проверены также plugin configuration changes и trace советника, ожидающего подтверждения до запуска основной модели.

Независимый сабагент провёл ревью scope, backend и UI. Найденные ошибки исправлены и покрыты проверками, включая сохранение открытого мобильного меню и клавиатурного фокуса после перерисовки.

## Границы реализации

Обычные чаты сохраняют прежний совместимый маршрут выполнения; новый агентный цикл используется в проектных чатах и Workflow. Root существующего проекта не перепривязывается: новую папку регистрируют отдельно. Workspace policy задаёт cwd и разрешения приложения, но не является sandbox ОС для команд. Финальная стадия debate сохраняет существующий контракт; общий новый budget ограничивает structured tool loops. Реальные облачные модели отдельно не прогонялись — доступная конфигурация облачных адаптеров указывала на локальный сервер.
