# Settings и Local profile: реализация и проверка UI-этапа

Проверено 20 сентября 2026 года на macOS arm64. Область работ — восемь пунктов пользовательской задачи и UI-часть `settings-profile-plugins-implementation-scope.md`. Изображения использованы как примеры структуры и взаимодействий; аккаунт, тарифы и статистика из референсов не переносились.

## Что реализовано

- Полноэкранная оболочка Settings со своей навигацией, группами Personal / AI System / Integrations / System, поиском по названиям и описаниям, Back to app и отдельными hash-адресами страниц. Основное приложение остаётся смонтированным под оболочкой; выполняющиеся запросы не отменяются при открытии Settings.
- Основная навигация Models / Workflow / Chat и история. Внизу — Local profile с нейтральным аватаром и меню Profile / Usage / Settings / Open data folder / About. Переключатель темы сохранён в прежнем месте.
- Компактные списки провайдеров и текущих интеграций с отдельными формами. `#/plugins` перенаправляет в `#/settings/plugins`. Локальный runtime, основная и расширенная память, входящий MCP-сервер Local Cognitive вынесены на отдельные страницы.
- Сохранение только явно изменённых полей через последовательную очередь. Пустой ввод секрета оставляет прежнее значение, Remove key явно удаляет его. Ошибка не показывается как Saved, а изменение во время запроса остаётся в черновике.
- Локальные UI-предпочтения сохраняются автоматически и не пересоздают runtime. Для остальных сущностей используется Save / Apply; проверки провайдеров и интеграций вызывают существующий backend.
- Profile и Account используют одну модель локального пользователя. Usage сообщает об отсутствии общего учёта. Неподдерживаемые страницы объясняют доступность функций без фиктивных переключателей.
- Общая политика Animations для CSS, стеклянной подсветки, JavaScript-переходов и React workflow: предпочтение включено по умолчанию, учитывается системный Reduce motion. Существующие темы и настройка Appearance используют одно состояние.
- Узкий desktop bridge открывает фактическую папку приложения без принимаемого от renderer пути; About показывает доступные метаданные сборки.

Новый PluginManager, каталог установки, OAuth/ConnectionService, биллинг, ledger и модельный tool-calling loop не добавлялись. Существующий MCP Client Manager сохранён. Telegram остаётся в backend, но отсутствует в новом UI. VS Code bridge, который backend ещё не реализует, показан недоступным; его сохранённая конфигурация сохраняется.

6. Новое изменение во время задержанного ответа: старый ответ не перезаписывает поле; следующий Apply сохраняет новое значение.

## Границы проверки

- Успех HTTP fixture подтверждает UI → backend → provider contract, но не доступность реальных OpenAI/Anthropic/Gemini/Notion аккаунтов. Их проверка требует соответствующих ключей и разрешённых внешних запросов. OAuth в этой версии отсутствует.
- Настройки local runtime сохранены через UI; запуск и генерация настоящей GGUF-моделью в этом прогоне не выполнялись. Проверки упакованных native runtime завершены успешно.
- Собрана и запущена версия macOS Apple Silicon (arm64). Intel/x64 и Windows в этом задании не проверялись.
- Сборка не подписана Developer ID и не нотарифицирована. Установка скачанного DMG на другом/чистом Mac с Gatekeeper требует отдельной проверки после подписания; настройки защиты macOS не изменялись.
- Исходные изменения README и ранее присутствовавшие пользовательские документы сохранены. Коммит не создавался.

Артефакты: `release/Local Cognitive AI System-0.1.0-arm64.dmg` и `release/mac-arm64/Local Cognitive AI System.app`.

## Voice: выбор и диагностика микрофона

Добавлена страница **Settings → Personal → Voice** (`#/settings/voice`), доступная также из меню Voice input в чате. Оба интерфейса используют одну модель состояния и последовательную очередь сохранения отдельных полей: микрофон, язык, модель распознавания. Выбор устройства не зависит от наличия модели Whisper. Для получения полных названий и списка устройств открывается кратковременный поток, который сразу закрывается после перечисления. При записи используется конкретный выбранный deviceId; после смены origin при перезапуске сохранённое имя помогает найти устройство заново. Отключённый микрофон не подменяется молча системным.

Test microphone показывает реальный уровень входа и имя используемого устройства. Звук этого теста не сохраняется и не транскрибируется; захват останавливается кнопкой, через 20 секунд, при уходе со страницы, скрытии окна или suspend. В записи используется частота AudioContext устройства, затем PCM преобразуется в 16 kHz для существующего Whisper runtime. Отключена обработка эха/шума, ненужная для односторонней диктовки, включён автоматический уровень. Слишком тихий вход и отсутствие распознанной речи теперь имеют разные сообщения; черновик сохраняется. Переход в Settings останавливает захват и завершает уже записанную диктовку в исходный чат. Логика LLM, workflow, моделей и MCP не изменялась этой правкой.

Проверено на изолированных данных:

- `npm test`: **274 passed, 1 skipped, 0 failed** (275 тестов). После последней правки стабильности dropdown повторно пройдены все **18 voice-тестов**. Покрыты отмена во время разрешения, поздние ответы, отключённое устройство, восстановление по имени, сериализация сохранений, ошибки, освобождение потока и сохранность исходного черновика.
